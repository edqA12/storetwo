# 暮安智护：跌倒全周期风险监测系统 MVP

> 更新日期：2026-09-24；当前运行目录：`C:\safe`。

这是“暮安智护——多模态AI老年人跌倒风险预警系统”的工程原型，现已形成“跌倒前风险评估—跌倒中事件识别—跌倒后人工复核”的双通道本地流程；家属通知和无人响应升级闭环尚未实现：

- 上传视频并生成带人体骨架、跌倒事件证据分和状态的检测结果视频；
- 使用浏览器摄像头进行连续姿态检测；
- 依据“快速下降或旋转 → 持续横卧”的时序证据判断跌倒；
- 保存告警时间、跌倒事件证据分、触发原因和截图；
- 在事件中心确认告警、标记误报、导出CSV；
- 支持左侧深度图、右侧RGB画面的组合视频，进行质量感知的双模态融合。
- 独立计算 Pre-Fall Risk Score，通过运动变化、稳定性、近跌倒和持久化个人基线偏离进行低/中/高风险分级；
- 按短时、24小时和30天三级时间窗口聚合风险，跨摄像头会话恢复同一监测对象的基线与历史窗口；
- 保存前置风险历史、等级变化和近跌倒事件，并在界面解释主要风险因素。

系统中的两个 0～100 指标必须严格区分：

- **Fall Event Score（跌倒事件证据分）**：当前短时间动作与跌倒事件特征的匹配程度；
- **Pre-Fall Risk Score（前置风险分）**：连续行为相对于已配置监测对象个人基线的工程风险评分。

两者都不是临床医学跌倒概率，也不能替代专业评估。

> 重要：本项目是学生科研和演示原型，不属于医疗器械，不能替代照护人员判断、临床诊断或紧急救援。不得让老年人模拟跌倒。

### 第一次运行

1. 确认电脑安装了Python 3.10～3.13，推荐3.11或3.12。
2. 双击 `setup.bat`。
3. 脚本会创建独立的 `.venv` 环境、安装依赖、下载轻量姿态模型并运行测试。

本机第一次安装需要下载PyTorch、Ultralytics和模型文件，耗时取决于网络速度。

### 日常启动

在 `C:\safe` 中双击 `start.bat`。浏览器会自动打开：

    http://127.0.0.1:7860

系统只监听本机地址，不会自动把摄像头或视频发布到互联网。

## 2. 使用方法

### 进入智护工作台

打开本地地址后，先显示“暮安智护”欢迎页，点击“进入智护工作台”使用系统，首次默认打开视频检测。
电脑端的四个功能常驻左侧；窄屏点击顶部“功能菜单”切换。左侧“返回首页”可回到欢迎页，再次进入会保留当前功能、已上传视频、检测结果、参数及历史分页；刷新浏览器会重新进入欢迎页，并按原有规则建立新会话。

进入工作台不会启动摄像头。使用实时监测时，摄像头权限和启动/停止仍由原有控件管理；摄像头处于开启状态时，返回首页会提示先停止摄像头，避免隐藏监测画面。切换功能页面不会主动重置监测。

### 视频检测

1. 点击左侧“视频检测”（窄屏先展开“功能菜单”）。
2. 上传MP4、AVI、MOV等常见视频。
3. 选择“普通RGB视频”或“RGB+深度组合视频（左深度、右RGB）”。
4. 选择人体检测置信度和处理速度。
5. 点击“开始检测”。
6. 查看结果视频、跌倒事件证据分曲线、前置风险曲线、近跌倒和本次告警事件。
7. 下载标注后的视频。

默认限制：单个视频不超过300MB、时长不超过10分钟。这些值可在 `config.yaml` 修改。

### 实时监测

1. 点击左侧“实时监测”（窄屏先展开“功能菜单”）。
2. 选择输入来源：浏览器RGB需允许摄像头权限；使用Astra Pro时选择“Astra Pro RGB＋深度”，先点击“连接Astra设备”，再点击“开始Astra监测”。停止后可点击“断开Astra设备”释放占用。
3. 让人物全身进入画面，并尽量固定摄像机。
4. 页面会分别显示前置风险分、跌倒事件证据分、当前状态、风险原因和处理帧率。
5. 跌倒条件成立时，画面显示红色告警并尝试播放提示音。
6. 可点击“我没事（标记误报）”或“确认告警”。

摄像头重新启动前建议点击“重置监测状态”。浏览器停止摄像头或清空输入时，系统也会重置会话状态。

### 事件中心

- 首次进入自动读取最近200条告警，默认每页20条；用“上一页 / 下一页”浏览，可切换为50条/页；
- 返回已经打开的页签会保留页码和数据；点击“刷新记录”读取最新快照并回到第一页；
- 点击表格中的事件查看截图和详情；
- 将事件标记为已确认、误报或已处理；
- 翻页或更改每页条数会清空旧选择，操作前请在当前页重新选择事件；
- 导出带UTF-8 BOM的CSV，最多最近5000条，不受当前页码和每页条数影响。

### 前置风险记录

- 首次进入自动读取最近500条风险记录，默认每页20条，可选50条或“全部（原表格模式）”；
- 趋势图保留最近500条窗口内的全部样本，以及前置风险分、短时、24小时、30天和深度空间证据5条曲线；翻页不会截断或重画趋势图；
- 点击“刷新风险记录”获取最新数据并回到第一页；返回已打开的页签保留现有快照；
- 点击“导出前置风险CSV”导出最多最近5000条记录，与当前表格分页无关。

两类表格仍保留全部字段，可横向滚动查看。分页模式下，表格自带排序、复制和全屏操作针对已加载的当前页；若需对原有历史窗口整表操作，请选择“全部（原表格模式）”。这里的“全部”指最近200条告警或500条风险记录，不代表数据库全部历史，也不改变CSV的既有5000条上限。新增检测记录不会自动挤动正在浏览的页面，需要刷新后查看。

## 3. 双通道分析原理

### 3.1 前置风险评估通道

系统按 Track 建立个人行为基线，持续分析运动速度变化、身体摆动与躯干稳定性，并识别“突然失衡后恢复站立、但没有形成确认跌倒”的近跌倒事件。系统还利用髋、膝、踝关键点识别“坐姿保持—起身—稳定站立”，记录起身耗时、过程稳定性、失败或重新坐下，并将异常结果纳入 Pre-Fall Risk Score。各指标先形成短时分，再按小时聚合24小时窗口、按日聚合30天窗口，最后通过带滞回的状态机输出 LOW、MEDIUM、HIGH，避免风险等级频繁跳变。

实时监测使用 `person_id` 将基线、近跌倒计数和三级窗口保存到 SQLite，并在新会话自动恢复；上传测试视频默认关闭该持久化，避免样例污染真实监测对象。深度分支先于 RGB 前置评估运行；`process_rgb_depth` 可接收同步 RGB 与原始深度帧，直接提取中位测距变化和纵向速度，并按质量参与前置风险融合。当深度质量不足或不可用时，模块继续使用 RGB 姿态运行，同时保存 `depth_degraded=true`。

### 3.2 跌倒事件检测通道

系统没有把YOLO单帧输出直接当作“跌倒”。流程如下：

    视频或摄像头
        ↓
    YOLO Pose人体框与17个骨架关键点
        ↓
    会话内轻量人体跟踪
        ↓
    躯干角、中心下降速度、旋转速度、运动幅度、横卧分数
        ↓
    时序状态机
        ↓
    正常 / 快速下降 / 疑似跌倒 / 已跌倒 / 躺卧异常

红色跌倒告警需要观察到：

1. 人体中心快速下降，或躯干在短时间内快速旋转；
2. 随后身体持续接近水平；
3. 横卧状态达到规定持续时间。

静止只会增加风险分，不是必需条件，因为跌倒后的人可能继续挣扎。若没有捕捉到快速下降证据，但人物持续横卧达到3秒且姿态质量足够，系统会记录黄色“疑似跌倒”二级事件；只有完整证据链才触发红色跌倒告警。

双模态模式会把组合画面拆分为深度图和RGB图：RGB分支继续使用YOLO姿态与状态机，深度分支根据有效像素、时序运动重心、下降幅度和强变化生成独立证据；融合引擎根据两路质量进行加权，并用可解释规则确认、降级或退回视觉判断。

## 4. 默认阈值

阈值均位于 `config.yaml`：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `confidence` | 0.30 | 人体框最低置信度 |
| `keypoint_confidence` | 0.25 | 关键点最低置信度 |
| `lying_enter_angle_deg` | 60° | 进入横卧判断的躯干角 |
| `lying_exit_angle_deg` | 40° | 退出横卧判断的躯干角 |
| `fast_down_velocity` | 0.20/s | 归一化人体中心下降速度阈值 |
| `fast_angle_velocity` | 48°/s | 躯干快速旋转阈值 |
| `lying_hold_s` | 0.6秒 | 有下降证据时的横卧确认时间 |
| `unexplained_lying_s` | 2秒 | 无下降证据时黄色提示时间 |
| `suspected_fall_hold_s` | 3秒 | 持续横卧二级事件确认时间 |
| `event_cooldown_s` | 9秒 | 同一人员重复告警冷却时间 |

这些只是MVP初始值，不代表临床阈值。正式实验应按受试者独立测试集、机位和场景调整，并报告混淆矩阵、跌倒召回率、精确率、F1、误报次数和告警延迟。

前置风险的五项权重、风险等级阈值、基线学习速度、近跌倒条件、Sit-to-Stand 条件、平滑和滞回时间均集中在 `config.yaml` 的 `pre_fall` 段。默认权重为运动异常25%、稳定性异常20%、近跌倒30%、起身能力10%、基线偏离15%。起身能力属于工程趋势监测，不是医学诊断指标。

## 7. 性能优化

本项目默认按无NVIDIA显卡的CPU电脑配置：

- 使用轻量 `yolo11n-pose.pt`；
- 输入尺寸512；
- 摄像头约每0.2秒提交一次最新画面；
- 模型推理全局串行，避免CPU内存耗尽；
- 视频可选择每2帧或3帧推理一次；
- 会话状态相互隔离，不共享跟踪历史。

历史页面的优化不依赖降低检测质量：首次打开才读取数据，服务端会话保存历史快照，仅将当前页发送给浏览器；重复切换不重查整表，翻页不重画曲线。历史读取、翻页、详情和状态操作不走Gradio排队接口，原有模型推理仍保持单并发；CSV导出回调保持原有队列配置。数据库增加时间与ID的组合索引，减少排序开销。

若事件中心或风险记录页仍卡顿，先使用20条/页，避免反复刷新或长时间使用“全部”模式；确认本地服务仍在运行，并查看启动窗口是否报错。切换页签不会自动停止摄像头，上传视频分析前应先停止实时摄像头，避免两项推理互相等待。分页不能解决服务退出、端口冲突或持续CPU满载导致的无法访问。

如果摄像头很卡：

1. 把 `image_size` 从512调到416；
2. 提高人体检测置信度；
3. 降低浏览器摄像头分辨率；
4. 后续可将模型导出为ONNX/OpenVINO，利用Intel硬件加速。

## 8. 已知边界

- 这是单摄像机、单房间、以单人为主的MVP，多人交叉时ID可能切换；
- 半身出画、严重遮挡、黑暗、镜头晃动会降低可靠性；
- 摄像机俯视角、床面高度和拍摄距离改变后需要重新验证阈值；
- 正常快速躺床、地面锻炼和快速坐地是重要误报场景；
- 浏览器可能阻止自动播放告警声音，因此视觉告警为主；
- 视频输出默认去除音轨，以保护隐私并简化浏览器兼容性；
- 上传双模态模式使用左右组合视频；实时页面支持浏览器RGB或Astra Pro软件配对的RGB＋原始深度；
- 左右组合视频中的8位深度可视化仍不能恢复标定测距；独立输入的原始16位/浮点深度才启用真实距离变化特征；
- 当前检测的是跌倒事件和姿态异常，还不等同于长期跌倒风险预测。
- 当前前置风险已支持跨会话基线及24小时/30天工程趋势，但仍不是跨天临床跌倒概率模型；Sit-to-Stand 在6个官方时间段真值上的事件级结果为 Precision 1.0000、Recall 0.6667、F1 0.8000。近跌倒在14段视频、1个逐帧复核正事件上的结果为 Precision/Recall/F1 1.0000、检测延迟0.360秒、视频级混淆矩阵 `[[13,0],[0,1]]`。两项样本量都很小，近跌倒正事件尤其只有1个，不能把100%外推为临床或跨场景性能。

更完整的26段统一专项集包含困难负样本：跌倒事件级 `TP/FP/FN=1/5/5`，Precision、Recall、F1均为0.1667；近跌倒F1为0.6667；Sit-to-Stand F1为0.7273。上述结果来自2026-09-02专项验收，本轮未重新运行真实视频评测，界面优化不代表这些指标有所提升。当前结论仍是“主要功能可运行，真实专项性能尚未通过最终验收”。

截至2026-09-24，Astra Pro 原始深度已接入实时界面；当前延期范围为人体三维测量、监测对象管理、高风险主动提醒及家属/照护者通知与无人响应升级闭环，以及P2功能。固定 `person_id` 的基线持久化不等于监测对象管理或通知功能已经完成。

建议至少测试：站立、正常行走、坐下、蹲下、弯腰、慢慢躺床、快速坐地、地面锻炼、跌倒后起身、跌倒后静止、半身出画、遮挡、黑暗和多人交叉。

## 9. 隐私与安全

- 所有推理和数据库默认在本机运行；
- 不要使用真实老人隐私视频进行公开展示；
- 数据采集前取得知情同意，并定义保存期限与删除机制；
- 告警截图和事件数据库位于 `data` 目录，转交电脑前应人工清理；
- 模拟跌倒只能由健康成年人在体操垫、护具和观察员保护下完成；
- 原型不能自动拨打真实急救电话。

## 10. RGB与深度多模态模式

跌倒事件通道采用质量感知的决策级融合：每个分支输出时间戳、风险、质量、状态和原因，再由融合引擎生成最终风险。前置风险通道则先计算深度下降、距离变化和纵向速度，再把深度空间分送入 RGB 姿态评估。视觉证据明确且得到深度支持时确认告警；两路冲突时降级为疑似；深度质量不足时自动退化为视觉模式。事件数据库通过 `event_modalities` 子表保存每个模态的结果和融合解释。

使用原始URFD左右组合视频时，选择“RGB+深度组合视频”。`00_ready_to_upload` 中的视频已经裁剪为纯RGB，应继续选择普通RGB模式。
