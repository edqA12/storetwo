# Astra Pro实时监测（任务四）

本说明记录任务四阶段；当前操作以[Astra实时页面使用说明](Astra实时页面使用说明.md)为准。

更新：2026-09-22。正式应用目录：`C:\safe`。

## 操作

1. 启动应用，进入“实时监测”。
2. 输入来源选择“Astra Pro RGB＋深度”，点击“开始Astra监测”。本地模型首次准备可能较慢，过期结果会丢弃。
3. 等待状态显示“RGB＋深度融合（软件配对）”。“RGB降级”表示当前深度未参与判断，原因显示在状态栏；预热期间短暂降级属预期。
4. 结束时点击“停止Astra监测”。若监测中断，先检查设备连接和其他程序占用，再停止并重新开始。重连后短期运动状态清空并重新预热，个人持久化基线保留。
5. 若第二页面提示设备占用，在原页面停止后再开始。返回首页前需停止监测；切换工作台功能页不会主动停止采集。浏览器后台节流可能影响推理连续性，使用时保持监测页前台。

## 数据与融合

OpenNI原始毫米深度转换为米，固定距离范围与无效值门控沿用任务三。UVC彩色与深度使用本机单调时钟的软件估计配对，RGB与深度运动各使用自己的时间戳。原始深度用于算法，预览仅用于显示。

有效帧进入现有`process_rgb_depth()`，沿用RGB人体检测、跟踪、前置评估与融合规则。深度缺失、过期、质量不足或失步时，深度权重为零，RGB时序继续；两路均不可用，或RGB不可用而无法执行当前人体检测时，清空画面和分数并显示“监测中断”。无人或未获得有效人体判断时不显示有效零分。

会话拥有独立视觉、深度与融合状态。深度故障不停止健康RGB流；采集层标记故障后须停止并重新开始恢复该流。重复帧不重复推理、事件和告警沿用现有统一出口。时钟重置、长时间RGB间断和重连清空短期状态。助手问答队列独立。

## 配置与限制

`config.yaml`中`astra.sdk_dir`为现有OpenNI SDK libs目录，`astra.result_max_age_s`控制过期推理结果丢弃；配对、有效率、距离和运动阈值仍在`multimodal`部分。没有更换驱动、模型、检测阈值或重新安装环境。

尚未验证硬件曝光同步、未做空间配准，因此深度只提供场景级运动证据，不能视为指定人体的对齐测距。多人、长时间稳定性、实际USB拔插恢复与临床有效性仍需专项验证。本轮连通性检查不能证明检测准确率提升，也不替代照护或人工确认。

诊断脚本：`.venv\Scripts\python.exe -B scripts\check_astra_live.py --model models\yolo11n-pose.pt`。脚本使用真实相机与本地模型，注入逻辑断流验证降级，并真正停止/重连相机；不写业务数据库、不保存媒体、不调用助手。仅在正式页面停止相机后运行。
