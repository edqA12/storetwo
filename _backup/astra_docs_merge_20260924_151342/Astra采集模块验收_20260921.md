# Astra Pro 独立采集模块验收

日期：2026-09-21。范围：任务二，独立相机采集模块。正式目标`C:\safe`。

## 变更

新增`camera_capture/`及独立检查入口，支持设备枚举、明确设备选择、连接、启动、停止、释放、有限缓存、后台采集线程、进程间独占及错误状态。帧携带设备来源、会话、序号、时间戳来源、像素格式和明确毫米单位。

不修改app.py、现有配置、检测/融合规则、个人基线、数据库、RAG和助手。没有安装新依赖，SDK继续使用用户的现有目录。界面尚未使用此模块。

## 候选验证

- 当前项目Python环境运行新增19项模拟/离线测试全部通过；覆盖生命周期、重启、设备选择、跨进程独占、失败清理、缓冲上限、副本隔离、缺帧/冻结、错误格式和SDK帧释放。
- 同一台真实Astra Pro运行三轮各约15秒：首次启动、停止后重启、断开后重连。
- 三轮深度接收累计分别467、481、468帧；彩色分别454、453、451帧。计数包含启动准备期，不能直接除以15作为精确帧率。
- 两路均为640×480；深度uint16毫米，彩色uint8 BGR。每轮新session_id，缓冲长度均不超过2，结束前两路数据均新鲜，未记录彩色解码错误。
- 最终状态disconnected。统计原件在工作区候选目录`candidate_hardware_result.json`，未保存图像。

## 限制

这是本轮新模块的采集验收，不能将此前官方示例10分钟测试算作新模块长时间验收。本轮未执行真实拔插、手机页面验证、长时间运行或模型效果评测。错误/冻结测试使用模拟输入。

设备默认单台自动选择；多设备须人工核对并指定两路标识。时间配对、空间配准、质量门控、人体对应和实时页面接入属于后续任务。采集的两路最新帧不等于同步帧对。
