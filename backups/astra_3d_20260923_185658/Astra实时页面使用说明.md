# Astra实时页面使用说明

更新：2026-09-22。正式目录`C:\safe`，本地访问`http://127.0.0.1:7860`。

## 如何使用

1. 进入实时监测，选择“浏览器RGB”或“Astra Pro RGB＋深度”。浏览器RGB继续使用原生摄像头启动/停止控件；Astra按以下步骤操作。
2. 点击“连接Astra设备”：识别并占用设备，此时不采集、不检测、不更新个人基线。
3. 点击“开始Astra监测”：等待彩色/深度数据及预热。检测画面和深度预览分开展示。
4. 点击“停止Astra监测”：停止采集和推理、清空当前结果，设备保持连接。
5. 点击“断开Astra设备”：释放占用，让其他页面或程序使用。切换回浏览器RGB也会断开本页Astra。

## 如何判断是否正常

| 页面状态 | 含义 |
| --- | --- |
| 等待数据 | 尚未启动、正在预热或刚丢弃过期结果 |
| 未检测到人 | 帧已处理，但没有检测到人体；分数不可用 |
| 人体质量不足 | 有检测框但证据不足，分数不可用，不更新个人基线 |
| 监测中断 | 当前无法完成检测；检查连接或占用后停止/重新开始 |
| RGB＋深度融合 | 两路参与当前跌倒事件判断，仍需核对质量 |
| RGB降级 | 本帧深度未参与跌倒事件判断；状态区展示原因 |

深度预览固定映射0.6–6米，黑色代表无效或范围外像素。能显示预览不等于深度已参与融合，应以“实际所用模态”和质量为准。深度只有场景级证据，未做人体空间配准。处理FPS是相邻结果完成时间的倒数，包含页面刷新间隔；首帧暂无速率。

多人场景无法确认基线归属时，保留当前场景检测但暂停个人前置风险更新。深度降级不自动否定有效RGB；有效RGB仍按既有基线规则处理。过期推理不写个人基线，上传视频不更新持久化基线。

## 记录与人工确认

使用原有“我没事（标记误报）”“确认告警”，或到事件中心处理。一个事件只记录一次；反复刷新不会覆盖首次截图、质量与回退原因，也不会再次播放同一事件告警。

事件及前置风险表右侧新增设备、所用模态、模态质量与回退原因；横向滚动查看，CSV同样保留这些列。数据库中还保存设备标识、采集会话、帧号、时间和配对偏差等可用字段。前置风险记录的模态按其自身是否使用深度保存。旧记录显示“未记录”，不会伪造来源。

## 页面关闭与占用处理

本实现不提供关闭页面后持续监测。正常关闭本页会断开设备；异常关闭、掉线或后台节流导致超过30秒没有刷新，后端会尝试停止并释放。切换工作台内功能页不会主动停止；请保持实时页前台，不将其作为无人值守后台服务。

若旧页面失去响应，在新页面选择Astra来源，点击“停止并释放设备（含其他页面）”，明确结束所有页面对本机这台相机的监测占用。原生SDK/推理阻塞时释放可能延后，必要时关闭并重启本应用；不要批量结束其他Python程序。
